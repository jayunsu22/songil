# ❓ 출입정보 질문 — 누구에게·카톡/문자 (2026-11-05)

사장님 11/5:
- "오늘업무에 블라블라 업체 보현나이스아파트 정보 묻는 거, 물어보는 담당자를 지정하고 카톡/문자 중 뭐로 물어볼지 정해야. 거래처 담당자 화면에서 정하면 될 듯."
- "출입정보 물어볼 때 업체 확인 질문도 포함되어 있는지."

## 고치기 전

- 결재함 '출입정보 질문' 카드는 공동현관·세대 비번·화장실 세 칸만 봤다. 업체 확인 질문은 빠져 있었다.
- 카드의 [진행해]는 9시에 아무것도 하지 않았다. 9시 처리에 이 카드가 연결돼 있지 않았다.
- 실제로 묻는 길은 노트북 텔레그램 [시작해]나 비서 "업체에 물어봐"였다. 이 길은 빈칸 + 확인 질문을 번호 질문으로 보내지만, 카톡 업체 방 하나로만 보냈다.

## 바꾼 것

- **담당자마다 [❓ 질문 담당]·[💬 카톡 / 📨 문자]**
  - 거래처 담당자(client.contacts)와 현장 발주처 담당자(site.owners) 줄 아래에 둔다.
  - 질문 담당은 거래처마다 한 명, 현장마다 한 명이다.
  - 발주처 담당자가 카톡이면 카톡방 이름 칸이 나온다.
  - 저장 필드: `ask`, `via`, `kakaoRoom`. store.normalizeOwners가 이 셋을 지운 것도 고쳤다.
- **정하는 순서** (`Share.askTarget`): 현장 발주처 담당자 중 질문 담당 → 거래처 질문 담당 → 거래처 담당자가 한 명이면 그 사람 → 첫 담당자.
  - 방법을 안 정했으면 카톡방 이름이 있을 때 카톡, 없으면 문자.
- **결재함 카드**
  - 내용: 빈칸(공동현관·세대 비번·화장실·필름 번호)과 '확인 질문 N개'. 기준은 `Share.siteAskItems`로 n8n 빈칸고르기와 같다. 둘 다 없으면 카드를 만들지 않는다.
  - 받는 사람 줄: "→ 실장님 · 💬 카톡".
  - [진행해]를 누르면 사람·방법을 고른다 (`Share.askChoices`, 정해 둔 것이 맨 위). 보낼 질문도 미리 보여 준다.
  - 고른 것은 decision.to에 `{ name, via, phone, kakaoRoom, client }`로 저장한다. 업무일정표 api.js는 카톡이면 번호가 없어도 저장한다.
- **9시** (업무일정표 run.js): `Share.askQuestion`으로 노트북 gaps.question과 같은 번호 질문을 만든다.
  - 문자: 사장님 폰으로 보낸다. 문자_답장 watch에 `fill: true`, `keys` = 빈칸을 넘겨서, 답이 오면 AI가 비번·화장실·필름 칸에 넣는다.
  - 카톡: 카톡_보내기에 `ask`로 맡긴다 (`ttl` 600분). 노트북 kakao_send가 gaps.run_ask로 그 방에 보내고 답을 7일 기다린다. 남은 질문은 다시 묻는다.
  - 그 사이 앱에서 다 받았으면 보내지 않는다.

## 결재함 ↔ 노트북 서로 알리기 (11/6 사장님: 노트북에도 알려줘야 안 헷갈림)

- 업무일정표에 `sd.asked` = { 현장id: { at, by: '결재함'|'노트북', via, who } }를 14일 둔다.
- 결재함이 9시에 보내면 `by: '결재함'`으로 적는다.
- 노트북 gaps.run_ask가 업체 방에 물으면 `report { action: 'asked' }`로 `by: '노트북'`을 적는다. 텔레그램 [시작해], 비서, 결재함 카톡 모두 이 길을 탄다.
- 노트북 gaps.check는 1시간마다 `report { action: 'askPlan' }`을 읽는다.
  - 결재함에서 [진행해]한 현장(plans)이나 결재함이 이미 물은 현장은 [시작해] 대신 텔레그램 "📋 결재함에서 묻기로 함 · 현장 → 실장님 · 📨 문자 (11/6 9시)"를 한 번 보낸다.
- 9시: 7일 안에 노트북이 이미 물은 현장은 보내지 않고 업무 내역에 '노트북이 이미 물음'을 남긴다.
- 결재함 카드: "✔ 이미 물어봄 · 노트북 💬 카톡 (방) · 11/6 — 답을 기다리는 중".
- 모든 화면 제목 옆에 앱 버전(v1106a)을 둔다. 앱을 새로 받았는지 확인하는 용도다.

## 9시 자동 발송 (2026-11-06 사장님)
"그냥 9시가 되면 자동으로 발송되게 해주면 된다."
- 결재하지 않은 ❓ 카드는 그날 9시에 정해 둔 질문 담당(`Share.askTarget`)에게 나간다. 그래서 흐름이 거래처 백업도 읽는다(`거래처읽기`).
- ❓ 카드의 [연기]는 [⏸ 멈춤]으로 보인다 (값은 later, 다시 누르면 풀림). [멈춤]·[내가]·[완료]를 눌러 두면 안 나간다. 멈춘 뒤 보내려면 [진행해], 노트북은 계획에서 빠지면 [시작해] 를 다시 띄운다. [진행해]로 사람을 고르면 고른 사람에게 나간다.
- 담당자가 없으면 보내지 않고 텔레그램으로 알린다.
- 오늘 카드를 9시 뒤에 [진행해] 하면 바로 보낸다. 저녁 8시 뒤에는 거절한다.
- 노트북 `askPlan` 은 결재 안 한 오늘·앞으로의 카드도 알려서 [시작해] 를 띄우지 않는다.
- 질문 글에서 "번호로 짧게 답 주시면 됩니다" 줄을 뺐다 (앱·노트북 같은 글).
- 필름 발주 [진행해]를 9시 뒤에 누르면 나가지 않는 문제는 남아 있다 (이번 범위 밖).
