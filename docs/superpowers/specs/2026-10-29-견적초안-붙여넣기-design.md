# 견적초안 ①② — 요청 붙여넣기 → 방문견적 초안 (2026-10-29)

업무자동화 1단계(sitenote `docs/업무자동화_프로젝트.md` 3절)의 첫 조각. 받은 견적 요청 글을 붙여넣으면
**방문견적에 품목이 체크되고 금액이 나온다.** 발행은 평소대로 방문견적에서 한다.
③④(빠진 것 질문·답 넣고 재계산)·⑤(저장함 상태·현장 만들기)는 다음 조각이다.

## 이미 있는 것을 그대로 쓴다 (사장님 2026-10-29: "방문견적·1분견적 양식 참조")
- **글 읽기 = 1분견적.** n8n `견적모드_V1`(`bD9Uw4A7XnBVnvGg`, POST `image-test`)의 텍스트 경로
  `GPT_Prompt(텍스트용)1` → `gpt노드1`(Gemini, temperature 0) → `품목명_정규화_검증1`(+`동의어_조회1`)이
  이미 "방문 2" → `{품목명: "방문", 수량: 2, 표시수량: "2개"}` 를 한다. 품목명은 시공품목정보의 `시공_품목명`.
- **금액 = 방문견적.** `MASTER.zones[].items[]`(체크_ID · 표시_품목명 · 옵션들[{품목명=시공_품목명, 단가…}])에
  `state.선택[체크_ID] = {수량, 난이도, 옵션}` 으로 체크하면 지금 계산·발행이 그대로 돈다.

`image-test` 를 그대로 부르지 않는다 — 부를 때마다 에어테이블에 고객 견적요청이 저장되고
텔레그램·푸시 알림이 나간다(`견적요청ID_저장2`, `텔레그램_발송1`, `견적푸시_발송`). 사장님 초안이 고객 상담으로 쌓이면 안 된다.

## 원칙
- 사람 말을 읽는 곳만 AI. 방 번호 펼치기·체크·금액은 규칙(순수 모듈, node 테스트).
- 못 알아본 말은 버리지 않고 '확인 필요' 로 남긴다 (조용히 빠지는 품목 금지).
- 카톡에 보내지 않는다. 이 조각은 앱 안에서 초안만 만든다.

## 화면
방문견적 화면 위쪽(업체 줄 아래)에 **📋 요청 붙여넣기** 칸.
- 출처 칩: 카톡 · 문자 · 통화 (통화는 갤럭시 통화녹음 텍스트를 붙여넣는다)
- 보낸 사람 칩: 고객 직접 · 업체. 업체면 이미 고른 업체(`state.업체`)의 단가 — 지금 방문견적 계산 그대로.
- 글 칸 + **[초안 만들기]**. 누르는 동안 "읽는 중…".
- 결과: 해당 품목이 체크되고 칸 아래에 한 줄 요약 —
  "5개 체크 · 필름 미정 · 꼭 알아야 할 것 3개 빠짐(사는 집인지 · 위치 · 다른 공정)".
  확인 필요 품목은 빨간 줄로 그 아래에 원문과 함께 ("쇼파 1개 — 방문견적에 없는 품목").
  이미 체크된 품목은 건드리지 않고 "이미 체크된 2개는 그대로 뒀어요".

## 흐름
```
붙여넣기 → n8n 견적초안_읽기 (1분견적 프롬프트 + 공통 정보) → request_draft.js (품목 → 방문견적 체크)
        → state.선택 에 더함 → 기존 방문견적 계산 → 합계
```

### n8n `견적초안_읽기` (POST `quote-draft-read`, 사장님 열쇠)
`견적모드_V1` 의 텍스트 경로만 복사한 새 흐름. 저장·알림 노드는 없다.
`받은요청`(webhook) → `동의어_조회`(airtable, 같은 표) · `프롬프트`(Code: 1분견적 프롬프트 + 아래 공통 정보 부탁)
→ `Gemini`(같은 자격증명) → `결과정리`(Code: JSON 꺼내기 + 1분견적 `품목명_정규화_검증1` 과 같은 정규화) → `응답`.
2단계에서 Gemini 만 Claude 로 바꾼다.

보냄: `{ 출처, 보낸이, 글, 오늘 }`
받음:
```json
{ "ok": true,
  "items": [{ "품목명": "방문", "수량": 3, "표시수량": "3개", "구역": "", "근거": "방문3세트" }],
  "공통": { "거주": "", "위치": "", "다른공정": "", "날짜": "", "필름": "", "평형": "" } }
```
- `items` 는 1분견적 출력에 `구역`("안방 문" → 방1, 말 안 했으면 "")·`근거`(원문 조각)만 더한 것.
- `공통` 은 글에 적힌 것만. 없으면 "". 지어내지 않는다.

### `request_draft.js` (순수 모듈, `test/request_draft.test.js`)
`체크하기(items, zones, 이미선택) → { 선택: {체크_ID: {수량, 난이도, 옵션}}, 건너뜀: [...], 확인필요: [...] }`

| 규칙 | 예 |
|---|---|
| 품목명이 옵션들[].품목명 에 있는 방문견적 품목을 찾는다. 옵션 순번이 `옵션` | 샤시(2중창) → 샤시1 의 2중창 옵션 |
| 구역을 말 안 했으면 구역 순서(거실·주방·현관·방1…방5) 에서 그 품목이 있는 구역을 앞에서부터 N개 | 방문 3 → 방1·방2·방3 › 방문 |
| 위 규칙의 결과 — 화장실문 2 → 거실 · 방1 (사장님 확인 2026-10-29) | 화장실문2세트 |
| 세트 = 문짝 + 문틀 (사장님 확인) — 방문·화장실문 품목은 원래 문+틀이라 그대로 | |
| 개수 품목은 구역마다 수량 1 | |
| m 품목: `표시수량` 이 "N세트" 면 그 구역의 같은 품목 N개(샤시1·샤시2)에 나눠 담고, "Nm" 면 첫 품목에 N | 샤시 2세트(6m) → 거실 샤시1 3m · 샤시2 3m |
| 구역을 말했으면 그 구역 | "안방 문" → 방1 › 방문 |
| 담을 품목이 모자라면 남은 개수는 확인 필요 | 방문 6개, 방5까지만 → 1개 확인 필요 |
| 방문견적에 없는 품목명 → 확인 필요 | 쇼파 1개 |
| 이미 체크된 품목은 건너뜀 | 두 번 눌러도 두 배가 안 됨 |

공통 정보는 `state.요청초안 = { 붙여넣기: [{출처, 보낸이, 글, 일시}], 공통 }` 에 둔다 → 자동저장·저장함·서버 백업을 탄다.
③ 에서 빠진 것 질문을, ④ 에서 답을 붙여넣어 다시 계산할 때 이걸 쓴다.

### 꼭 알아야 할 것 (견적 공통 필수, 사장님 2026-10-29)
**사는 집인지(거주 중/빈집) · 위치(주소·동·호수) · 다른 공정과 겹치는지.** 여기에 필름 번호와 희망 날짜를 더해
빠진 것을 요약 줄에 보여 준다. 질문 문구로 만드는 것은 ③.

### 사장님 열쇠
`owner-key.js` 의 OWNER_PATHS 에 `quote-draft-read` 추가 (파일 머리 주석대로 sitenote 복사본도 같이).
웹훅은 먼저 열쇠 없이 만들어 시험하고, 확인 뒤 headerAuth 를 켠다.

## 오류
- 웹훅 실패·시간 초과(90초): 글은 칸에 그대로, "AI 가 답하지 않았어요. 다시 눌러 주세요." 체크는 건드리지 않는다.
- 품목을 하나도 못 찾음: "품목을 못 찾았어요. 아래 목록에서 직접 체크해 주세요."
- 방문견적 마스터를 아직 못 받았으면 버튼을 막고 이유를 보여 준다.

## 시험
1. `node test/request_draft.test.js` — 규칙 표의 각 줄 + 시험 1·2.

3. 웹훅: 열쇠 없이 시험 1·2 글로 직접 호출 → 응답 JSON. `image-test` 와 같은 글을 넣어 품목·수량이 같은지 비교.

금액은 방문견적 그대로. 요약: 꼭 알아야 할 것 3개 + 필름·날짜 빠짐.

글: `싱크대 상하부장이랑 거실 샤시 2개 필름 얼마에요` → 주방 › 싱크대, 거실 › 샤시1·샤시2 (단창, 각 3m).

## 정한 것 — 1분견적 규칙을 따른다 (사장님 2026-10-29)
1분견적과 견적요청 v2 의 규칙이 달랐다. 초안은 1분견적 규칙을 그대로 쓴다 (프롬프트를 복사하므로 저절로 그렇게 된다).
- 샤시 종류를 안 쓰면 **단창**.
- 길이를 안 쓰면 샤시 **1개=3m**, 가구(수납장·신발장·붙박이장·냉장고장) **1세트=2m** 로 채운다.
  업무자동화 문서의 "길이 ?" 는 쓰지 않는다. 채운 길이는 방문견적 수량 칸에서 고친다.
- 싱크대는 1분견적 프롬프트에 기본 길이가 없어 1m 로 읽힌다. 근거에 숫자가 없으면 **보통 길이**
  (싱크대 8 · 상부장 4 · 하부장 7m, 발행 견적 68건 중앙값)로 채우고 결과 칸에 "📏 보통 길이로" 표시 (사장님 2026-10-29).
