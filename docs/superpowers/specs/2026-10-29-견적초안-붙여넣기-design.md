# 견적초안 ①② — 요청 붙여넣기 → AI 초안 (2026-10-29)

업무자동화 1단계(sitenote `docs/업무자동화_프로젝트.md` 3절)의 첫 조각. 받은 견적 요청 글을 붙여넣으면
견적요청 v2 화면(`quote_request.js`)의 줄이 자동으로 채워지고 금액이 나온다.
③④(빠진 것 질문·답 넣고 재계산)·⑤(저장함 상태·현장 만들기)는 다음 조각이다.

## 원칙
- 사람 말을 읽는 곳만 AI. 품목 이름 맞추기·방 번호 펼치기·금액은 규칙(순수 모듈, node 테스트).
- AI 가 모르는 값은 지어내지 않는다. 길이를 모르면 **"길이 ?"** 로 두고 합계에서 뺀다.
- 못 알아본 말은 버리지 않고 빨간 '확인 필요' 줄로 남긴다 (조용히 빠지는 품목 금지).
- 카톡에 보내지 않는다. 이 조각은 앱 안에서 초안만 만든다.

## 화면
견적요청 화면 맨 위에 **📋 요청 붙여넣기** 칸.
- 출처 칩: 카톡 · 문자 · 통화 (통화는 갤럭시 통화녹음 텍스트를 붙여넣는다)
- 보낸 사람 칩: 고객 직접 · 업체 방. 업체 방이면 이미 고른 업체(`state.업체`)의 단가를 쓴다 — 지금 계산 그대로.
- 글 칸 + **[초안 만들기]**. 누르는 동안 버튼은 "읽는 중…".
- 결과: 줄이 ② 에 들어가고, 칸 아래에 한 줄 요약 — "5줄 넣음 · 필름 미정 · 길이 ? 0개 · 확인 필요 0개".
  이미 같은 품목 줄이 있으면 덮지 않고 건너뛰며 "이미 있는 품목 2개는 그대로 뒀어요" 라고 알린다.

## 흐름
```
붙여넣기 → n8n quote-request-draft (AI: 말 → 일반 품목) → request_draft.js (일반 품목 → 관리자 품목 줄)
        → state.요청.줄 에 더함 → 기존 RequestPrice 계산 → ② 줄 · ③ 합계
```

### n8n `견적요청_초안` (POST `quote-request-draft`, 사장님 열쇠)
`현장관리_카톡정리`(`wYQuLwpJZEPNwWQd`)와 같은 4노드: 프롬프트(Code) → Gemini 2.5 flash(HTTP, 기존 자격증명) → 결과정리(Code) → 응답.
2단계에서 Gemini 노드만 Claude 로 바꾼다.

보냄: `{ 출처, 보낸이, 글, 오늘 }`
받음:
```json
{ "ok": true,
  "items": [{ "종류": "방문", "구역": "", "개수": 3, "세트": true, "시공범위": "", "샤시종류": "", "길이": null, "필름": "", "근거": "방문3세트" }],
  "공통": { "주소": "", "날짜": "", "필름": "" } }
```
- `종류` 는 정해진 목록만: 방문 · 화장실문 · 세탁실문 · 실외기실문 · 현관문 · 중문 · 샤시 · 싱크대 · 싱크대 상부장 · 싱크대 하부장 · 붙박이장 · 수납장 · 신발장 · 냉장고장 · 아트월 · 몰딩 · 걸레받이 · 기타.
  목록 밖은 결과정리에서 `기타` 로 바꾸고 `근거` 를 남긴다.
- `길이` 는 글에 숫자로 적힌 것만. 없으면 null.
- 관리자 품목 이름 목록은 AI 에 보내지 않는다 — 이름 맞추기는 앱의 규칙이 한다 (목록이 길고, 규칙이 테스트 가능하다).

### `request_draft.js` (순수 모듈, `test/request_draft.test.js`)
`펼치기(items, 관리자품목이름들, 이미있는줄이름들) → { 줄들, 건너뜀, 확인필요 }`

| 규칙 | 예 |
|---|---|
| 세트 = 문짝 + 문틀 → 시공범위 `문+틀 양쪽면 시공` (사장님 확인 2026-10-29) | 방문3세트 |
| 구역 없는 방문 N개 → 방1·방2·…·방N 의 `방k문+틀` | 방문 3 → 방1문+틀, 방2문+틀, 방3문+틀 |
| 화장실문 2개 → `거실화장실문`, `방1화장실문+틀` / 1개 → `거실화장실문` (사장님 확인) | 화장실문2세트 |
| 구역이 말해졌으면 그 구역 품목 | "안방 문" → 방1문+틀 |
| 같은 구역에 N개면 끝 번호로 펼침 | 거실 샤시 2개 → 거실샤시1, 거실샤시2 |
| 샤시 종류를 안 쓰면 2중창 (사장님 기준) | |
| 관리자 목록에 없는 이름이 나오면 그 줄은 확인 필요 | 방문 6개인데 방5까지만 있음 → 6번째는 확인 필요 |
| 길이 품목인데 길이 null → `길이모름: true` | "싱크대 필름" |
| 필름 없음 → 기본 필름 단가, `필름미정: true` | |
| 같은 품목명 줄이 이미 있으면 건너뜀 | 붙여넣기를 두 번 눌러도 줄이 두 배가 안 됨 |
| `기타` → 확인 필요 줄 (품목명 = 근거, 금액 0) | |

### 금액 — "길이 ?"
지금 `RequestPrice` 는 길이가 비면 보통 길이(샤시 3m 등)를 채운다. 손으로 고를 땐 그대로 두고,
**`줄.길이모름` 이 true 이고 길이를 아직 안 고른 줄만** 보통 길이를 쓰지 않는다 → 문제 `길이없음` → 합계에서 빠짐.
② 줄에는 "길이 ? (보통 3m)", ③ 합계 옆에는 "길이 모르는 품목 N개 제외". 길이를 고르면 `길이모름` 을 지운다.

### 저장
`state.요청.붙여넣기 = [{ 출처, 보낸이, 글, 일시 }]` — 원문을 남긴다 (③④에서 답을 붙여넣어 다시 계산할 때 쓴다).
자동저장·저장함·서버 백업은 지금 `state.요청` 경로를 그대로 탄다.
`state.요청.원문`(현장관리 앱 내역 요약용)은 지금처럼 고른 품목 이름.

### 사장님 열쇠
`owner-key.js` 의 OWNER_PATHS 에 `quote-request-draft` 추가 (파일 머리 주석대로 sitenote 복사본도 같이).
웹훅은 먼저 열쇠 없이 만들어 시험하고, 확인 뒤 headerAuth 를 켠다.

## 오류
- 웹훅 실패·시간 초과(90초): 글은 칸에 그대로 두고 "AI 가 답하지 않았어요. 다시 눌러 주세요." 줄은 건드리지 않는다.
- AI 가 품목을 하나도 못 찾음: "품목을 못 찾았어요. ① 에서 직접 골라 주세요."
- 관리자 품목을 아직 못 받았으면(첫 실행·오프라인) 초안 버튼을 막고 이유를 보여 준다.

## 시험
1. `node test/request_draft.test.js` — 아래 시험 1 포함, 규칙 표의 각 줄.
2. `node --test test/*.test.js` 전체 (RequestPrice `길이모름` 추가 포함).
3. 웹훅: 열쇠 없이 시험 1·2 글로 직접 호출 → 응답 JSON 확인.
4. 화면: 로컬 서버로 quote_pro.html 견적요청 → 붙여넣기 → 줄·합계 확인.

### 시험 1 · 현장에서 지나가던 분 (고객 직접, 카톡)
글: `방문3세트, 화장실문2세트 견적내주세요`

| 줄 | 품목 | 시공범위 | 금액 |
|---|---|---|---|
| 1 | 방1문+틀 | 문+틀 양쪽면 시공 | 221,000 |
| 2 | 방2문+틀 | 문+틀 양쪽면 시공 | 221,000 |
| 3 | 방3문+틀 | 문+틀 양쪽면 시공 | 221,000 |
| 4 | 거실화장실문 | 문+틀 양쪽면 시공 | 단가표대로 |
| 5 | 방1화장실문+틀 | 문+틀 양쪽면 시공 | 단가표대로 |

필름 미정(기본 9,000), 길이 ? 없음, 확인 필요 없음. 방문 금액은 단가표 6.5m × (25,000 + 9,000).

### 시험 2 · 길이 모름
글: `싱크대 상하부장이랑 거실 샤시 2개 필름 얼마에요` → 싱크대 1줄 + 거실샤시1·거실샤시2(2중창) 2줄, 세 줄 모두 길이 ? 라 합계 0원,
"길이 모르는 품목 3개 제외". 합계가 0원이어도 줄은 남는다 — ③ 에서 길이를 묻는 질문이 된다.
