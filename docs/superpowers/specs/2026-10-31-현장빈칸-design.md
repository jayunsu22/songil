# 현장 빈칸 채우기 A·B (카톡 '비서' 4단계) — 설계

사장님 결정 10/31 (인계 문서 14절). A = 기본·출입(공동현관 비번 `pwLobby`, 세대 비번 `pwUnit`, 화장실 `toilet`), B = 필름(`films` 에 번호 있는 줄).

## 흐름
1. **빈칸 찾기** — 노트북이 1시간마다 n8n `site-gaps` (사장님 열쇠) 를 부른다. n8n 이 현장관리 백업 Airtable(`apprglBOGXhKQN4cl` 현장·거래처 표)에서
   오늘~7일 안에 시작(`date`)하고, 숨기지 않았고, A·B 중 빈칸이 있는 현장을 `[{id, client, name, date, missing, known}]` 로 준다.
2. **텔레그램 묻기** — 아침 8시~저녁 8시에만, 현장마다 **한 번만** (`state.json gaps[현장id]`):
   `[현장] 그린워크1차 1104동 604호 (봄애, 11/25 시작)\n공동현관 비번·세대 비번·화장실 위치·필름 정보가 비어 있습니다. 업체에 물어볼까요?` + [시작해] [나중에].
   `config.json client_rooms` (`{"봄애": "봄애실장님"}`) 에 거래처가 없으면 버튼 없이 "카톡 방 짝이 없습니다 (config.json client_rooms)".
3. **[시작해]** — 콜백 `k|번호|ask` → n8n 카톡_버튼 이 할 일로 둠 → 노트북 `jobs.poll` 이 가져가 방을 열고 `kakao_window.send_text`:
   ```
   안녕하세요. 실장님~
   그린워크1차 1104동 604호 (11/25 시공)
   공동현관 비번, 세대 비번, 화장실 위치, 필름 정보(위치별 번호) 알려주세요.
   ```
   (비어 있는 것만). 카톡을 업체 방에 보내는 건 이 버튼을 눌렀을 때만 — '김정헌 방만' 규칙의 유일한 예외.
   보낸 뒤 `state.json asks[방]` 에 {현장 id·이름·날짜·물은 칸·known, at} (7일). 텔레그램 "보냈습니다".
   [나중에] 는 n8n 이 표시만 바꾸고 끝 (다시 안 물음).
4. **답 읽기** — 물어본 방은 7일 동안 알릴 방(`watch_rooms`)에 더해진다(목록이 비어 있으면 원래 모든 방). 새 글을 읽을 때(`read_and_report`)
   그 방에 물어본 현장이 있으면, 평소 분류와 따로 **비번 가리지 않은** 새 글(사장님 글 뺀 것)을 n8n `kakao-digest`(현장관리 📥 카톡 정리 그대로)에 보낸다.
   sites = 물어본 현장들 → 현장이 여럿이면 AI 가 동·호수로 짝. 결과 중 `field`(pwLobby·pwUnit·toilet) 와 `films` 만 쓴다.
5. **넣기 (우편함)** — 노트북이 n8n `site-fill` 에 `{siteId, field|films, value, room}` 를 둔다 → 텔레그램 "[현장] 넣었습니다 · 현장 / 공동현관 비번: … (현장관리 앱을 열면 들어갑니다)".
   다 받은 현장은 asks 에서 뺀다.
6. **현장관리 앱** — 열 때·다시 보일 때·5분마다 `site-fill-take` → 이 기기에 있는 현장만 바로 칸에 넣고(📥 카톡 정리 [저장] 과 같은 방법: `fieldSrc` 출처 '방 날짜', 필름은 `Kakao.mergeFilms`)
   넣은 번호를 `done` 으로 돌려준다. 이 기기에 없는 현장은 우편함에 남는다(14일 뒤 지움). 토스트 "카톡에서 N칸 채웠어요".

## 왜 우편함인가
현장관리 원본은 기기 localStorage, Airtable 은 한쪽(기기→서버) 백업. 노트북이 Airtable 에 쓰면 기기에 안 보이고 다음 백업 때 덮인다.
양쪽 맞추기는 앱 수정이 크고 충돌 규칙이 필요 → 사장님이 우편함 선택(10/31).

## 만들 것
- n8n 새 흐름 **현장관리_빈칸** (`songil/n8n/site_fill/`): `site-gaps`(Airtable 읽기 → 고르기), `site-fill`(넣기), `site-fill-take`(앱이 가져가기·`done` 지우기). 모두 사장님 열쇠, 우편함은 staticData.
- n8n **카톡_버튼**: `ask` 동작 = 할 일, 표시 "⏳ 업체에 묻는 중".
- 노트북 `gaps.py`: 빈칸 확인·텔레그램, [시작해] 처리(질문 보내기), 답 → digest → site-fill. `reader.py`·`chatlist.py`·`jobs.py`·`n8n_send.py` 연결.
- sitenote: `fill.js`(순수: 우편함 항목 → 현장 patch) + `app.js` 가져오기, `owner-key.js` 경로 추가(두 저장소 복사본).

## 지키는 것
- 글 내용·비번은 노트북 파일에 남기지 않는다 (asks 에는 현장 이름·물은 칸만; known 은 질문 때 빈칸이라 비번 없음).
- 사장님 열쇠·백업키는 사장님이 넣는다. 카톡 DB 복호화 안 함. sitenote 배포·push 는 사장님께 묻는다.

## 시험
- 노트북: 빈칸 고르기·묻기 한 번만·8~20시·질문 글·digest 결과 거르기·asks 정리 (윈도우 없이).
- 앱: fill.js 단위 시험 (node test).
- n8n: 빈 현장으로 site-gaps 실제 호출, site-fill → take → done 왕복.
