# 견적 저장함 → 현장관리자 품목 체크 보내기 설계

날짜: 2026-09-26
상태: 사용자 승인 (구현 계획 작성 전)

## 배경

현장견적(`quote_pro`)에서 견적을 낸 뒤 계약이 되면, 필름현장관리자(`admin`, jayunsu22.github.io)에서
새 현장을 개설하고 **품목 표에서 시공할 품목을 하나씩 체크**한다. 견적에 이미 적힌 품목을
다시 손으로 고르는 일이 반복된다.

견적 저장함은 폰 localStorage(`quote_pro_box_v1`)에만 있어 관리자 앱(다른 도메인)이 읽을 수 없다.
그래서 **견적 앱 쪽에서 현장관리자 서버로 보낸다.**

## 결정 사항 (사용자 확인 완료)

| 항목 | 결정 |
|---|---|
| 방향 | 견적 저장함 → 현장관리자 (반대 방향 아님) |
| 새 현장 개설 | 하지 않음. 현장은 현장관리자에서 직접 개설하고, 여기서는 **이미 있는 현장**을 고른다 |
| 보내는 것 | 품목 체크(활성화)만. 사진 보내기는 이번 범위 밖 |
| 체크 해제 | 하지 않음. 추가만 한다 |
| 크라운몰딩 | 현장관리자의 **몰딩**으로 체크 |
| 세탁실문 / 실외기실문 | **거실세탁실문** / **거실실외기실문** |
| 가벽 | 거실만 **가벽**에 연결, 다른 구역 가벽은 짝 없음 |

## 확인된 사실 (2026-09-26 실측)

- `songil.netlify.app` 오리진에서 아래 웹훅 호출 시 CORS 허용됨 → **n8n·admin 수정 불필요**
  - `GET  film-admin-get-v2` → `{ projects, masterItems, ... }`
  - `GET  film-quality-get-v2?code=<현장 recordId>` → `{ activeItems, ... }`
  - `POST film-quality-save` `{ type: 'toggle_item_create', projectCode: <recordId>, itemName }`
    (admin.js `saveZonePendingChanges` 가 쓰는 것과 동일한 요청)
- 두 앱의 품목 체계가 다르다.
  - 견적: `구역`(전체공통/현관/거실/주방/세탁실/실외기실/방1~5/방N베란다/방1드레스룸) × `표시_품목명`(방문, 샤시1, 붙박이장, 몰딩 (30평) …)
  - 현장관리자 `masterItems`: `품목명` 하나(안방문+틀, 방2샤시, 거실샤시1, 싱크대 …) + `구역`
  - 현장관리자는 방1을 **안방**이라 부른다.

## 1. 화면 흐름

```
견적 앱 저장함 줄 [🏗 현장으로]
  → 현장 고르기 시트   (film-admin-get-v2 의 projects 중 보관함 아닌 것, 시공일자 최신순,
                        견적 이름과 겹치는 글자가 많은 현장을 맨 위 + 강조)
  → 미리보기 시트     (선택 현장의 activeItems 조회 후 계산)
       ✅ 체크될 품목   구역별 묶음, 줄마다 체크박스(기본 켜짐, 끄면 제외)
       ☑️ 이미 체크됨   회색, 건너뜀
       ⚠️ 짝 없음       "웨인스코팅, 알판 … 은 현장관리자에서 직접 골라주세요"
       [n개 보내기]
  → 품목마다 toggle_item_create 순차 호출, "12/15" 진행 표시
  → 완료 토스트 + 저장함 항목에 보낸기록 { 현장ID, 현장명, 일시, 건수 } 저장
     저장함 줄에 "→ 인천 도림로8 벽산블루밍 (9/26 보냄)" 표시
```

- 저장함 항목의 `상태`(견적 state 스냅샷)에서 선택 품목을 읽는다. 지금 화면에 열린 견적이 아니어도 된다.
- 일부 실패 시: 성공/실패 건수를 보여주고, 다시 누르면 (activeItems 재조회로) 성공한 건 자동으로 건너뛰고 나머지만 재시도.
- 네트워크 오류로 목록/상세 조회 실패 시 시트에 오류 문구 + 다시 시도 버튼.

## 2. 짝짓기 모듈 `quote_to_site.js` (UMD, node 테스트 가능)

순수 함수. DOM·fetch 없음.

```
짝짓기(견적선택목록, 방수, 현장품목명목록) → { 짝: [{ 구역, 견적품목, 현장품목 }], 짝없음: [{ 구역, 견적품목 }] }
```

- 입력 `견적선택목록`: `[{ 구역, 표시_품목명 }]` (원래 구역명 기준. 사용자가 바꾼 구역 표시명 아님)
- 규칙이 만든 **후보 이름들을 순서대로** 보고, `현장품목명목록`에 **실제 있는 첫 번째**를 쓴다. 하나도 없으면 짝 없음.
  → 현장관리자에 없는 품목이 새로 생기는 일은 없다.
- 결과 `현장품목`은 중복 제거(여러 견적 줄이 같은 현장 품목으로 모이면 한 번만).

### 구역 접두어
| 견적 구역 | 접두어 |
|---|---|
| 방1 | 안방 |
| 방2~방5 | 방2~방5 |
| 방N베란다 | (방N 접두어)+베란다 — 방1베란다 → 안방베란다 |
| 방1드레스룸 | 안방드레스룸 |
| 거실 / 주방 / 현관 | 거실 / 주방 / 현관 |

### 품목 규칙 (후보 순서대로, `P` = 구역 접두어)
| 견적 품목 | 후보 |
|---|---|
| 방문, 문짝, 문틀 (방N) | `P문+틀` |
| 샤시1, 샤시2 (방N, 방N베란다) | `P샤시` |
| 샤시1, 샤시2 (거실·주방) | `P샤시1`/`P샤시2` → `P샤시` |
| 붙박이장, 붙박이장문짝, 붙박이장틀, 수납장, 수납장문짝, 수납장틀 | `P수납장` |
| 등박스 | `P등박스` |
| 화장실문, 화장실 문짝 (거실·방1) | `P화장실문+틀` → `P화장실문` |
| 화장대 (방1, 방1드레스룸) | `화장대` |
| 문짝 (방N베란다) | `P문+틀` |
| 거실베란다 통로문, 베란다 중문 | `거실베란다문` |
| 아치 | `P아치문틀` |
| 아트월 / 가벽(거실) | `아트월` / `가벽` |
| 싱크대, 싱크대 상부장·하부장·전체 (평형 포함) | `싱크대` |
| 냉장고장, 냉장고장문짝, 냉장고장틀 | `냉장고장` |
| 세탁실문 / 실외기실문 | `거실세탁실문` / `거실실외기실문` |
| 현관 신발장1·2 / 현관문 / 중문·중문짝·중문틀 | `신발장1`·`신발장2` / `현관문` / `현관중문` |

### 전체공통 (몰딩·걸레받이·크라운몰딩, 평형/실측 무관)
- 몰딩·크라운몰딩 → 대상 구역 각각 `P몰딩`
- 걸레받이 → 대상 구역 각각 `P걸레받이`
- 대상 구역 = 거실, 주방, 현관, 안방, 방2 … 방(`방수`) — 견적 state 의 `방수`(기본 3)
- 여기도 실제 있는 품목만 (예: 현관몰딩은 있지만 없는 조합은 조용히 건너뜀)

위 표에 없는 조합은 전부 **짝 없음**.

## 3. 견적 앱 수정 범위

- `quote_to_site.js` (신규) — 짝짓기 모듈
- `test/quote_to_site.test.js` (신규) — node:test. 실제 `film-admin-get-v2` masterItems 품목명
  목록을 고정값으로 넣고 위 규칙 표의 대표 케이스 + 전체공통 펼치기 + 짝없음 + 중복제거 확인
- `quote_pro.html` — 스크립트 포함, 현장 고르기/미리보기 시트 마크업
- `quote_pro.js` — 저장함 줄 버튼, 시트 동작, 웹훅 호출, 보낸기록 저장·표시
- `quote_style.css` — 시트/목록 스타일 (기존 저장함 시트 스타일 재사용 우선)

admin(github.io 저장소)과 n8n은 수정하지 않는다.
