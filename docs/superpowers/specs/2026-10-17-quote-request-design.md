# 견적요청 작성하기 · 견적요청 내역 — 설계

날짜: 2026-10-17
목업: `docs/superpowers/mockups/quote-request-mockup.html`(전체 흐름), `docs/superpowers/mockups/quote-request-batch-mockup.html`(입력 3단계)

## 왜

현장에서 일하는 중에 카톡으로 견적요청(사진, 또는 "안방 분합창 1" 같은 글)이 오면
제대로 못 보고 빠뜨리는 견적이 생긴다. 빠진 견적은 뒤에 고치기 어렵고 신뢰에도 문제가 된다.
요청을 받는 즉시 짧게 받아두고, 사진·글을 한꺼번에 품목으로 바꿔 방문견적으로 발행하고,
거래처 화면에서 요청·발행 내역을 한눈에 보이게 한다.

## 결정 사항 (사용자 확인)

| 항목 | 결정 |
|---|---|
| 견적 발행 | 방문견적(`songil.netlify.app` quote_pro)에서 발행. 새 견적서 화면을 만들지 않는다 |
| 입력 화면 위치 | **A안** — 방문견적 사이트에 '요청 입력' 화면. 현장관리 앱에는 [견적요청 작성하기] 버튼과 내역 목록만 |
| 사진 입력 | 카톡 사진을 한꺼번에 올리고, 여러 장 골라 위치·품목을 한 번에 지정 |
| 글 입력 | 카톡 글을 통째로 붙여넣으면 줄마다 위치·품목·수량으로 바뀜 |
| 글 해석 | 방문견적 품목명·구역명 + **단어장**(예: 이중창=2중창, 하나=1). 못 알아본 줄은 빨간 줄, 사용자가 고치면 단어장에 저절로 추가 |
| 사진 없는 품목 | 필름현장관리자에 올라간 시공사진(시공 전/후)에서 품목명으로 걸러 고름 |
| 고른 시공사진 | 고객 견적서(/q/)의 해당 품목 아래에도 보여줌 |
| 샤시 | 기존 방문견적처럼 종류(단창/2중창/시스템)를 고름 |
| 금액 | 방문견적 계산(quote_calc) 그대로 |
| 놓침 알림 | 따로 안 만든다. 요청은 사용자가 직접 넣으므로 앱 안 '답장 전' 배지로 충분 |

## 범위 밖 (이번에 안 함)

- 푸시/텔레그램 알림
- '안 됨(미수주)' 상태와 사유 기록
- AI로 글 해석
- 정산견적(settle) 연동 — 참고만

## 구성

세 곳을 고친다. 모두 기존 저장소다.

### 1. 방문견적 `D:/songil` (주 작업)

**요청 = 저장함 항목 + `요청` 칸.** 저장함(quote box)은 이미 폰 저장 + 서버 백업(pro-box-sync, 백업키) +
사진 백업이 다 돼 있으므로, 요청을 따로 저장하지 않고 저장함 항목에 아래 칸을 더한다.

```
항목.요청 = { 접수일시: ISO, 원문: '카톡 글 그대로', 거래처ID, 거래처명 }
```

상태는 따로 적지 않고 계산한다: 품목 0건 → **답장 전**, 품목 있음·현장코드 없음 → **작성 중**,
현장코드 있음 → **발행**. 저장함 30건 제한은 그대로 — 발행 뒤 저장함에서 지워도 발행 기록(서버의
발행목록)이 남으므로 내역은 사라지지 않는다.

**새 순수 모듈 (DOM·네트워크 없음, node 테스트 — 기존 `quote_calc.js` 패턴)**

- `request_parse.js` — `해석(글, 사전) → 줄[]`
  - 사전 = { 품목들: [{품목명, 옵션들}], 구역들: [...], 단어장: {별칭: 정식} }
  - 한 줄 → `{ 원문, 구역|null, 품목명|null, 옵션|null, 수량, 확인필요: bool, 건너뜀: bool }`
  - "이랑/하고/,/도" 로 한 줄에 여러 품목이면 여러 줄로 나눈다. 위치는 앞 품목 것을 이어받는다
  - 숫자 없으면 수량 1. 한글 수사(하나·둘·셋…)는 단어장 기본값으로
  - 품목을 못 찾은 줄은 `확인필요`. 품목도 위치도 없는 인사말 줄은 `건너뜀`
  - 샤시 옵션 단어(이중창·2중창·단창·시스템)는 옵션으로
- `request_merge.js` — `합치기(글줄[], 사진라벨[]) → 항목[]`
  - 키 = 구역+품목명. 같은 키의 글 줄과 사진은 한 항목(출처 '사진+글'). 수량은 글의 숫자
  - 글만 → 출처 '글만', 사진 없음 표시. 사진만 → 수량 1, 출처 '사진만'
  - 라벨 없는 사진 → '미지정' 묶음 (발행 전 경고)
- `request_wordbook.js` — `배우기(단어장, 원문토막, 정식값)` / 기본 단어장(수사, 이중창 등)

**새 화면 — 요청 입력 (quote_pro 안 시트, 탭 3개)**

1. ① 사진: 여러 장 한꺼번에 추가 → 격자에서 여러 장 골라 → 위치 칩 + 품목 칩(자주 쓰는 순, 🔍 전체 검색) → 일괄 지정.
   기존 사진 저장(QuotePhotos/IndexedDB)과 태그(체크_ID) 구조를 그대로 쓴다. 지금의 한 장씩 태그 화면은 그대로 둔다
2. ② 글: 붙여넣기 → `request_parse` 결과를 줄로 보여줌. 줄을 눌러 고치면 `request_wordbook.배우기`
3. ③ 견적 항목: `request_merge` 결과. 글만 있는 항목에 [시공사진에서 고르기]. 빨간 카드(위치?·미지정 사진)가 남으면 다음으로 넘어갈 때 알림.
   [방문견적으로] → `state.선택`(체크·수량·종류)과 사진 태그를 채우고 기존 계산 화면으로. 발행은 기존 그대로

**시공사진 고르기** — 품목명으로 필름현장관리자 작업사진(시공후/시공전)을 최근 순으로 받는 새 webhook.
사진은 Airtable 첨부라 주소가 몇 시간 뒤 만료되므로, **고르면 그 이미지를 받아 폰 사진으로 복사**해서
일반 사진처럼 태그한다. 그러면 견적서에 사진을 싣는 기존 발행 경로를 그대로 탄다(새 견적서 코드 없음).

**단어장 보관** — 서버 백업(백업키). 새 webhook `pro-wordbook` (get/put). 폰에도 캐시해서 오프라인에서도 해석.

### 2. 현장관리 앱 `D:/n8n_거래처별_현장관리`

- 거래처 화면 메모 내역 아래 **'견적요청 내역'** 접이식 칸 + [견적요청 작성하기] 버튼
- 버튼 → `https://songil.netlify.app/quote_pro.html?req=1&client=<거래처ID>` 새 창. 방문견적은 그 거래처를 골라 둔 채 요청 입력 시트를 연다
- 목록 = 같은 백업키로 `pro-box-restore` 를 읽어
  - 저장함 항목 중 `요청.거래처ID == 이 거래처` → 답장 전/작성 중
  - 발행목록 중 `현장관리_거래처ID == 이 거래처` → 발행 (금액·날짜·/q/ 링크)
  - 최근 순. 답장 전 개수를 칸 제목 배지로
- 이 앱은 읽기만 한다. 고치기·지우기는 방문견적에서

### 3. n8n

- `pro-box-restore` 의 `published` 에 `현장관리_거래처ID` 가 실려 오는지 확인, 없으면 추가 (발행 때는 이미 보내고 있음)
- 새 `work-photos-by-item` — 품목명 → [{url, 현장명, 날짜, 전후}] 최근 N장
- 새 `pro-wordbook` — 백업키로 get/put
- 사진 받기가 CORS 로 막히면 이미지 중계 webhook 추가 (구현 첫 단계에서 확인)

## 오류·예외

- 서버 못 읽음(현장관리 앱 내역): "내역을 못 받았습니다 · 다시" 줄. 버튼은 계속 동작
- 백업키 없음: 현장관리 앱 설정 안내. 방문견적은 기존 업체키 입력 흐름
- 시공사진 0장: "이 품목 시공사진이 없습니다" + 건너뛰기
- 발행 전 빨간 카드 남음: 막지 않고 확인창 (기존 이중계산경고처럼 알리기만)
- 같은 거래처 같은 현장 이름으로 또 요청: 저장함 기존 규칙(현장ID로 덮어쓰기)을 따르되, 요청은 새 현장ID로 시작하므로 따로 쌓인다

## v2 (2026-10-18) — 품목설정 → 사진·옵션 → 합산·메모

사용자가 업무 순서를 다시 정함. **v1 의 글 탭·글 해석·단어장 학습은 삭제**하고 아래로 바꾼다.
목업: `docs/superpowers/mockups/quote-request-v2-mockup.html`

| 단계 | 내용 |
|---|---|
| ① 품목 | 필름현장관리자 품목설정을 그대로(탭 문+틀·샤시·가구·몰딩·기타, 이름 방2문+틀 …). 체크만 |
| ② 사진·옵션 | 고른 품목만 정산견적과 같은 줄로. 시공범위(문)·샤시 종류·길이 또는 '1개 Xm'·필름·난이도. 카톡 사진 일괄 넣고 골라 줄에 붙이기, 시공사진에서 고르기 |
| ③ 합산·메모 | 줄 합 + 부가항목(부자재비·식대·퀵비, 정산견적과 같은 선택지) + 필름 추가 + 부가메모 → [방문견적에 넣기] |

**계산 (사용자 결정):** 에어테이블 '시공품목정보'(1분견적·방문견적 표)의 식 그대로
`줄 금액 = 필름 m × (인건비단가 + 필름단가) × 난이도` — 자재비단가 자리에 줄에서 고른 필름 단가.
예) 문틀 2m × (47,000 + 9,000) = 112,000 (사장님 확인). 품목이 빠지면 그 줄 인건비도 빠지므로 품수를 따로 안 고친다.

**애매한 다섯 가지 (사용자: 추천대로):**
1. 시공범위: 문틀만 → 표의 '문틀'(중문은 '중문틀') 줄, 문짝만 → '문짝'('중문짝') 줄. 한쪽면·앞면만·뒷면만 → 같은 줄에 절반 m, 문선만 → m 직접
2. 샤시: 종류 선택(기본 2중창) → 표의 샤시(2중창)·샤시(단창)·시스템샤시 줄. 2중창은 1m당 필름 1.7m
3. 몰딩·걸레받이·크라운: 방별 품목이라 길이 기준 줄(실측), 평형별 줄은 안 씀
4. 표에 없는 품목(프레임·파티션·계단·사무실벽·TV박스·거울프레임·샤시틀옆 기둥·2층 품목): 줄에서 '단가 정하기'(인건비 원/m, 1개 필름 m) → 폰과 서버(단어장 웹훅의 '단가:품목명' 열쇠)에 기억. 아치문틀은 표 '아치'(25,000/m) 기본 5m
5. 상가샤시(양쪽/한쪽)는 샤시 종류 선택지로

**연결 규칙:** `request_price.js` 의 `표줄이름()` (테스트 `test/request_price.test.js`, 기대값은 표 숫자로 손계산).
길이 품목 보통 길이: 샤시 3, 수납장 3, 냉장고장 2, 신발장1 5·신발장2 3, 싱크대 8, 등박스 12, 가벽 10, 아치 5 (v1 에서 잰 발행 견적 중앙값). 몰딩은 길이를 골라야 금액이 나온다.
기본 m 는 표 값을 쓴다 (예: 현관문 5m - 관리자 앱은 3m 지만 견적은 표 기준).

**넣기:** 줄 → 방문견적 `state.직접품목` (id = 줄 id 'rq…', 구역 = 관리자 구역이 방문견적에 있으면 그대로·없으면 전체공통, 인건비/자재비 나눠서). 부가 금액은 전체공통의 직접품목. 사진 태그 = 줄 id 라 그대로 따라감. 부가메모 → `state.메모`. 발행은 방문견적 그대로.

**데이터:** 새 n8n `현장견적_요청마스터` (YLT043Ej0ECMlZPd, GET request-master, 사장님 열쇠) → { 시공품목(관리자, 뒷정리 제외), 단가표(정산 단가표: 자재단가=필름, 부가항목), 품목정보(시공품목정보, 평형별 제외) }.
