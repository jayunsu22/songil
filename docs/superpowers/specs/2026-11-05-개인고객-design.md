# 👤 개인고객 — 탭 하나에 모으기 (2026-11-05)

사장님 11/5: 블로그·소개로 오는 1회성 개인고객을 거래처로 등록하면 너무 많아진다. 목업: `docs/superpowers/mockups/private_customer_mockup.html` ("이대로 만들어").

## 결정

거래처 구조를 바꾸지 않는다. 이름이 **개인고객**인 거래처 탭 하나에 고객을 현장으로 넣는다. 일정·필름·인원·결재함·비서·정산은 모두 거래처 안의 현장 단위라 그대로 동작한다. 정산은 이미 현장별이고, 앱에 세금계산서 기능은 없다.

- **판별:** 이름으로 한다 (`Share.isPrivateClient`, 띄어쓰기 무시). 서버(`gaps.js`)도 같은 이름을 본다. 데이터 칸을 늘리지 않으려고 이름을 쓴다.
- **탭 만들기:** 거래처가 있는 앱을 처음 열 때 저절로 만든다 (`settings.privateTabMade`). 지우면 다시 만들지 않는다.
- **고객 칸:** 이름·연락처는 발주처 담당자 첫 줄(`owners[0]`, role '고객'). 새 칸을 만들지 않아 문자·비서 연락처록·AS 고객 고르기가 그대로 쓴다. 경로는 `site.source`(블로그·소개·기타), `site.sourceBy`.

## 화면

- **탭:** 찾기(이름·전화번호·아파트, 끝난 현장 포함), 진행 / 끝남 / 블로그 / 소개. 고객 이름이 먼저 보인다.
- **끝남:** 시공이 지났고 잔금을 받음 (`payDone` 또는 입금 기록). 안 받았으면 진행에 남는다.
- **＋ 고객:** 이름·연락처·경로·소개한 사람·현장. 같은 번호의 예전 현장이 있으면 "전에 시공한 고객이에요" (모든 거래처에서 찾음).
- **현장 화면 맨 위 고객 칸:** 고칠 수 있고, 전화·문자 버튼.
- **시공 7일 안에 빈 칸(공동현관·세대 비번·주차·화장실)이 있으면 [📨 문자로 물어보기]:** 내용을 고쳐 사장님이 눌러야 나간다. 사장님 폰(SMS Gateway).
- **🔀 다른 거래처로 옮기기:** 모든 현장의 정보 탭에 있다. 현장의 거래처만 바꾼다 (거래처별 사진은 그대로).
- 개인고객 탭에는 "카톡 정리"를 보여 주지 않는다 (업체방이 없음).

## 서버

`n8n/site_fill/gaps.js`: 개인고객 현장은 빈칸 목록에서 뺀다 → 노트북이 "카톡 방 없음" 알림을 안 보낸다. 필름 주문 알림은 그대로 나간다. 노트북 코드는 안 바뀐다.

## 비서

`boss_chat.js`: 현장 상태에 고객 이름(`customer`)을 넣어 "이다라 고객님 비번 바뀜"을 알아듣게 한다. 찾기에도 고객 이름을 넣었다. 번호는 지금처럼 안 보낸다.

## 고객에게 카톡으로 (11/5, 목업 `customer_kakao_mockup.html`)

- 고객 칸에 **카톡방 이름**(`site.kakaoRoom`, 비우면 고객 이름). 못 받은 정보 칸에 [📨 문자로] [💬 카톡으로]. 결과는 `site.kakaoLast`로 고객 칸에 표시 (10초마다 확인).
- 앱 → n8n 카톡_보내기(`watch: { siteId, name, until, keys }`) → 노트북 `kakao_send.poll` → `report.send_exact`.
- **정확히 같은 방에만:** 열린 창 → 목록(`open_room`, 비슷한 방이 열리면 닫음) → 카톡 검색(`chatlist.search_open`). 검색은 메인 창의 Edit 칸에 WM_SETTEXT·Enter로 메시지만 보내 채팅방에 글이 잘못 들어가지 않는다. 전송 전 `send_text`가 창 제목을 다시 확인한다.
  - **같은 이름의 방이 둘이면 구분하지 못한다.** 먼저 열리는 방으로 간다. 목업의 "비슷한 방이 여럿이면 알려 줌"은 이름이 다른 방까지만 해당한다.
  - 검색칸 동작은 이 PC에서 시험할 수 없다. 노트북에서 `python reader.py --find-room 방이름` (보내지 않고 열었다 닫음).
- **지켜보기:** 보낸 뒤 `state.cust_watch[방]` (현장 id·이름·날짜·칸 이름만, 글·값 없음). 시공일이 지나면 저절로 뺀다. `chatlist.check`의 지켜볼 방에 더한다.
- **답 읽기:** `assist.handle`이 그 방이면 `client: 개인고객`, `siteId`를 넘겨 그 현장만 보게 한다 (카톡_비서 프롬프트). 칸은 우편함으로, 답장은 업체방과 같은 기준.
- **다시 묻기:** 값이 온 글 뒤에도 비번·화장실이 남으면 텔레그램 [물어봐]/[내가 할게]. [물어봐]면 3시간 뒤 노트북이 보낸다 (저녁 9시~아침 8시는 미룸). 주차는 비서가 칸에 넣지 못해 세지 않는다.

## 안 한 것

- 고객이 문자로 준 답은 앱에 저절로 안 들어간다. 사장님 폰에 오는 답을 읽는 길이 없어서다. 칸에 적거나 비서에게 말한다.
- 결재함의 "출입정보 질문" 항목은 개인고객도 그대로 나온다.
