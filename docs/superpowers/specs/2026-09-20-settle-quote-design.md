# 현장 정산견적 (품수 기반 사후 견적) 설계

날짜: 2026-09-20
상태: 사용자 승인 (구현 계획 작성 전)

## 배경

지금 있는 현장견적(`quote_pro`)은 **품목별 단가 × 수량**으로 시공 전에 견적을 내는 도구다.
이와 별개로 거래처 현장에서는 **일부터 먼저 하고 끝난 뒤 정산 견적**을 내는 방식이 쓰인다.
이 방식은:

- 인건비를 **품수(몇 품 들어갔는지) × 품단가**로 계산하고
- 자재비는 **품목별 자재소모량(m)** 합산 × **자재별 m당 단가**로 따로 계산하며
- **부자재비 · 식대 · 퀵비/택배비** 같은 부가 항목이 덧붙는다.

이 견적을 품질관리(블로그자동화) 관리자 앱의 **현장 카드에서 바로 시작**할 수 있게 한다 —
그 현장의 작업목록에 이미 "실제 작업된 품목"이 있기 때문이다.

## 결정 사항 (사용자 확인 완료)

| 항목 | 결정 |
|---|---|
| 품수 | 현장마다 사장님이 직접 입력 (자동 계산 없음) |
| m단위 품목 길이 | 견적 화면에서 길이(m) 입력 |
| 자재 단가 | 설정 화면에서 여러 개 등록해두고 줄마다 선택 |
| 출력 | 공유 링크 (`/s/<코드>`), 기존 `/q/<코드>` 견적서와 같은 방식 |
| 구조 | **1안**: 작성/보기/설정 페이지는 songil(netlify) 저장소, 관리자 앱에는 버튼만 |
| 디자인 | 기존 현장견적(`quote_style.css`)과 같은 컬러 토큰·화면 구조 (헤더 고정, 카드형 섹션, 하단 고정 합계바, 발행 시트) |

## 1. 화면 흐름

```
관리자 앱(admin.js) 현장 카드 [💰 현장견적]
  → https://songil.netlify.app/settle.html?site=<현장 recordId>     (작성)
       ├ ⚙ 단가 설정 (같은 페이지의 모달)
       └ [견적서 발행] → 8자 코드 발급
            → https://songil.netlify.app/s/<코드>?n=<base64url 현장명>  (보기 · 카톡 공유)
```

- 작성 화면은 관리자 전용. admin과 같은 PIN 잠금(같은 SHA-256 해시 상수 재사용, localStorage 키 `settleUnlocked`).
- 작성 중 상태는 `localStorage['settle_state_<현장ID>']`에 자동 저장 → 나갔다 와도 유지. 발행하면 스냅샷이 서버에 확정된다.
- `?site=` 없이 열면 "관리자 앱의 현장 카드에서 열어 주세요" 안내만 보인다.

## 2. 작성 화면 (`settle.html` + `settle.js` + `settle_style.css`)

기존 현장견적과 같은 뼈대: sticky 헤더 → 카드 섹션들 → 하단 고정 합계바 → 발행 시트.

### 헤더
- 현장명(읽기 전용, 마스터에서) · 시공일자
- 버튼: `⚙ 설정`, `새로 시작`(자동 저장 초기화, 확인창)

### ① 인건비
```
품수 [ 8 ]  ×  품단가 [ 250,000 ▾ ]  =  2,000,000원
```
- 품단가 select 는 정산단가표의 `구분=품단가` 항목. "직접 입력" 선택 시 숫자칸 활성.
- 품수는 소수 허용(0.5품).

### ② 자재비
- **전체 자재** select 한 개(맨 위): 고르면 모든 줄의 자재가 그 값으로 바뀐다(줄마다 다시 바꿀 수 있음).
- 그 아래 현장 작업목록의 품목이 **구역 → 우선순위** 순으로 나열. 구역이 바뀔 때 구역 제목 줄.
- 줄 구성:

| 체크 | 품목명 | 수량/길이 | 소모량 | 자재 |
|---|---|---|---|---|
| ☑ | 안방문+틀 | `1` 세트 (−/+) | 6.5m | [LX 프리미엄 ▾] |
| ☑ | 안방샤시 | 길이 `[3.2]` m | 3.2m | [LX 프리미엄 ▾] |
| ☐ | 거실수납장 | (흐리게) | | |

- 작업목록에 있는 품목은 **모두 체크된 채로 시작** (시공완료 여부 무관 — 정산 시점엔 끝나 있고, 빠진 건 체크 해제).
- 세트/개 품목(`길이입력` 미체크): 수량 스테퍼(기본 1). 소모량 = 마스터 `자재소모량` × 수량.
- 길이 품목(`길이입력` 체크): 길이 입력칸(m, 소수 1자리). 소모량 = 마스터 `자재소모량`(m당) × 길이. 길이 비어 있으면 소모량 0 + 줄을 주황색 테두리로 표시.
- 소모량 숫자를 탭하면 직접 수정 가능(수정한 줄은 `직접` 뱃지). 마스터에 값이 없는 품목은 빨간 `0m`로 표시해 눈에 띄게.
- `+ 품목 추가`: 작업목록에 없는 품목을 이름/소모량/자재 직접 입력으로 추가(현장에서 추가로 한 작업).
- 블록 하단 **자재별 소계**: 자재마다 한 줄 `LX 프리미엄 12,000원/m × 41.7m = 500,400원`.

### ③ 부가 항목
- 정산단가표의 `구분=부가항목` 줄이 이름 + 금액 입력칸으로 나열(기본값은 단가표의 `단가`, 0이면 빈칸).
- `+ 직접 추가`: 이름/금액 임의 줄.
- 금액 0/빈칸인 줄은 견적서에 안 나간다.

### ④ 합계 · 발행
- 하단 고정바: 총액 + `견적서 발행` 버튼(총액 0이면 비활성).
- 발행 시트(기존 `pubSheet` 구조): 메모(견적서에 나감) · `부가세 별도 표기` 체크(기본 켬) · 발행 확인.
- 발행 성공 → 시트 안에 링크 + `복사` + `카톡 공유`(모바일이면 `navigator.share`) + `견적서 열기`.
- 같은 현장에서 다시 발행하면 **새 코드**(이전 링크의 금액은 그대로).

## 3. 계산 규칙 (`settle_calc.js`, DOM 없는 순수 모듈)

```js
SettleCalc.줄소모량(줄)           // 직접수정값 ?? (길이입력 ? 마스터소모량×길이 : 마스터소모량×수량)
SettleCalc.자재별소계(줄들, 자재표) // [{자재ID, 자재명, 단가, 소모량합, 금액}] — 체크된 줄만, 소모량 소수 1자리
SettleCalc.합계(state, 자재표)     // { 인건비, 자재비, 부가, 총액, 자재소계:[...] }
```

- 인건비 = 품수 × 품단가
- 자재별 금액 = round(소모량합 × 단가). 소모량합은 소수 1자리로 반올림한 뒤 곱한다(견적서에 보이는 숫자와 계산이 일치해야 한다).
- 총액 = 인건비 + Σ자재별 금액 + Σ부가항목
- 자재 select 값이 자재표에 없으면(설정에서 삭제됨) 줄을 `자재 없음` 경고로 표시하고 소계에서 제외 — 조용히 0원으로 넘어가지 않는다.
- `test/settle_calc.test.js`(node, 기존 `quote_calc.test.js`와 같은 방식)로 검증: 세트/길이/직접수정/자재 묶음/반올림/자재 없음.

## 5. 백엔드 — 새 n8n 워크플로우 `정산견적_백엔드`

기존 `현장견적_발행`/`현장견적_조회`와 같은 소형 워크플로우 패턴. CORS 헤더 `*`.

| 웹훅 | 입력 | 출력 |
|---|---|---|
| `GET settle-master?site=rec…` | 현장 recordId | `{ 현장:{현장명,시공일자}, 작업목록:[{시공품목,밑작업완료,시공완료}], 시공품목:[{품목명,구역,우선순위,자재소모량,길이입력}], 단가표:[{id,항목명,구분,단가,순서,사용여부}], 회사정보:{업체명,대표전화,홈페이지주소} }` — Airtable 5개 조회를 병렬로 |
| `POST settle-publish` | `{ 현장ID, 현장명, 스냅샷, 총액, 부가세_별도표기, 메모 }` | `{ success, 견적코드 }` — 코드는 혼동 글자 뺀 31자 알파벳 8자 랜덤 |
| `GET settle-quote?id=코드` | 견적코드 | 정산견적 레코드 + 회사정보 (없으면 `{error}`) |
| `POST settle-settings` | `{ 단가표: { create:[…], update:[{id,…}], delete:[id] }, 품목소모량: [{품목명, 자재소모량, 길이입력}] }` | `{ success }` — 품목은 품목명으로 찾아 update |

작업목록 조회는 `현장명` 링크 필드에 site recordId가 포함된 레코드만 (기존 v2와 같은 필터 방식).

## 6. 견적서 보기 (`settle_view.html` + `settle_view.js`, 경로 `/s/<코드>`)

- `_redirects`: `/s/*  /settle_view.html  200` (catch-all 위).
- `netlify/edge-functions/partner-og.js`: `/s/` 도 `/q/`와 같은 분기에 넣고 제목 `"<현장명> 정산 견적서"`, 설명 `"섬세한손길 시공 정산 견적서"`.
- 구성(위→아래): 업체명·대표전화 · 현장명 · 발행일 → **인건비** 한 줄(`8품 × 250,000원`) → **자재비** 자재별 한 줄(`단가 · 소모량합 m · 금액`) + `품목 내역 보기` 접기(품목별 수량/길이·소모량·자재) → **부가항목** → 합계(부가세 별도 문구) → 메모.
- 스타일: `quote_style.css` + `quote_view.css` 재사용, 정산 전용 차이만 `settle_view.css`.

## 7. 단가 설정 (⚙ 모달, `settle.html` 안)

탭 3개:
1. **자재단가** — 줄: 항목명 · 원/m · 순서 · 사용 토글 · 삭제. `+ 추가`.
2. **품단가 · 부가항목** — 같은 줄 구조(품단가는 원/품, 부가항목은 기본 금액).
3. **품목 소모량** — 시공품목 전체를 구역 순으로: 품목명(읽기) · 소모량 · 길이입력 체크. 값 없는 품목이 위로 오도록 정렬.

`저장` 한 번에 `settle-settings` 호출 → 성공 시 마스터 다시 받아 화면 갱신. 사용중인 자재를 삭제하려 하면 경고(줄에서 `자재 없음`으로 보이게 됨).

보관함 카드에도 표시(정산은 보관 후에 하는 경우가 많다). push 시 `admin.html`의 `?v=` 갱신.

## 9. 에러 처리
