# 카톡 읽기 3단계 — 텔레그램 버튼으로 처리 (설계, 2026-10-31)

사장님 합의 '비서' 구조의 3단계: 노트북이 보낸 텔레그램 요약에 버튼을 붙이고, 사장님이 누르면 노트북이 처리한다.
앞 단계: `kakao_reader/chatlist.py` (B안: 알릴 방 새 글 → 1분 뒤 열어 읽기 → n8n 카톡_분류 → 텔레그램).

## 정한 것 (사장님 10/31)
- **방법 ①**: n8n 이 버튼 누름을 받아 '할 일' 로 적어 두고, 노트북이 확인할 때마다 가져간다.
  (안 쓴 것: 노트북이 텔레그램에 직접 묻기 — 봇 열쇠가 노트북에 있어야 함 / 링크 버튼 — 누를 때마다 브라우저)
- **첫 버전 버튼**
  - 견적 문의 → [가견적 발행] [나중에]
  - 하자보수·일정 변경·결제·기타·분류 실패 → [확인함]
  - 현장관리 반영·답장 초안·AS 등록은 다음 단계.
- 가견적 링크는 **텔레그램으로만**. 카톡 보내기는 지금처럼 김정헌 방만.

## 조사한 것
- 요약은 '현장 견적서작성_발송' 봇(자격 `4iGW8eEwhNuTpFHa`)이 보낸다 (n8n 카톡_알림 `dnBRN9hF2GrCJZhZ`).
- n8n 의 텔레그램 트리거는 '가맹점_텔레그램_등록봇' 하나뿐이고 다른 봇(필름견적 알림봇 `bLOZVbD5uoCZyZpA`)을 쓴다 → 견적서작성 봇에 트리거를 새로 걸어도 부딪치지 않는다. (봇 하나는 신호를 한 곳으로만 보낼 수 있다.)
- 노트북은 밖에서 오는 연결을 못 받는다 → 노트북이 가져가는 방식.

## 흐름
```
노트북(chatlist.read_and_report)
  └ 요약 + 버튼(콜백 'k|<할일번호>|<동작>') → n8n 카톡_알림 → 텔레그램
사장님이 버튼 누름
  └ n8n 카톡_버튼 (텔레그램 트리거, callback_query)
       - 누른 사람이 사장님 챗ID(가맹점 p_001) 인지 확인
       - '받았습니다' 표시(answerCallbackQuery), 메시지 버튼을 지우고 끝에 '⏳ 가견적 발행 중' / '✔ 확인함' / '⏸ 나중에'
       - 가견적 발행만 '할일' 표에 적음 {번호, 동작, 누른때, 가져감=false}
노트북(reader.py, 확인할 때마다)
  └ n8n 카톡_할일 (GET kakao-jobs, 사장님 열쇠) → 안 가져간 할 일을 주고 '가져감' 으로 바꿈
  └ 처리 → 결과를 카톡_알림 으로 텔레그램 (가견적 링크 또는 실패 이유)
```

## 단위
### n8n
- **카톡_알림** (고침): 받는 것에 `buttons: [[{text, data}]]` 를 더한다. 있으면 인라인 버튼을 붙여 보낸다. 없으면 지금과 같다.
- **카톡_버튼** (새로): 텔레그램 트리거(callback_query) → 사장님 확인 → 표시 바꾸기 → 발행이면 할일 표에 적기.
- **카톡_할일** (새로): POST `kakao-jobs` (사장님 열쇠) → 안 가져간 할 일 목록을 돌려주고 가져감 표시.
- 할일 표: n8n Data Table `카톡_할일` (번호·동작·누른때·가져감). 글 내용은 넣지 않는다.

### 노트북 (`kakao_reader/`)
- `chatlist.read_and_report`: 요약을 보낼 때 할일 번호(짧은 무작위 6자)를 만들고 버튼을 붙인다.
  `state.json` 의 `jobs[번호] = {방 제목, 종류, 글 지문들, 사진 장수, 만든때}` — **지문만, 글 내용 없음** (원칙).
  7일 지난 것은 지운다.
- `jobs.py` (새로): 할 일 가져오기·처리.
  - 가견적 발행: 그 방을 다시 열어(이름으로 줄 찾기, `open_room`) 글을 복사 → 지문이 맞는 글만 → 사진이 있으면 그 방 창에서 `kakao_photo.save_latest_photos` → 방 닫기
    → `quote_bot.publish(글, 사진, client=방 이름(client_aliases 적용))` → 텔레그램에 링크 (`[카톡] 가견적 발행 · 류춘화 …`).
  - 지문이 하나도 안 맞으면(방 글이 지워짐 등) 발행하지 않고 텔레그램으로 이유.
- `reader.py`: 확인할 때마다 `jobs.poll()` (가견적은 몇 분 걸려서 한 번에 하나).

## 오류
- 노트북이 꺼져 있을 때 누른 버튼 → 할일 표에 남아 있다가 켜지면 처리.
- 같은 버튼을 두 번 → n8n 이 첫 번째에 버튼을 지우므로 두 번째는 없음. 노트북은 처리한 번호를 `state.json` 에 남겨 다시 하지 않는다.
- 가견적 실패(거래처 못 찾음 등) → 지금 김정헌 방과 같은 처리('업체미확인' 거래처, ⚠ 알림).
- 사장님이 아닌 사람이 누름 → 무시.

## 시험
- 노트북: 버튼 붙이기·할일 처리(가짜 n8n 응답)·지문 맞추기를 `unittest` 로.
- n8n: 카톡_할일 은 직접 호출해 확인, 카톡_버튼 은 실제 버튼을 사장님이 눌러 확인.
- 노트북 실가동: 견적 문의 요약 → [가견적 발행] → 텔레그램에 링크.
