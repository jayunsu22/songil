# 설계 7-2 — 사진 매칭 정확도 측정

정답(필름 코드)을 아는 사진으로 실제 검색을 돌려, **정답이 몇 등에 오는지** 잰다.
지금까지 매칭 가중치들은 근거 있는 시작값일 뿐 실사진으로 검증된 값이 아니었다.

## 사진

`D:\n8n_1분견적(필름)\검증사진\` 에 샘플북 쪽 사진을 넣는다.
쪽마다 실린 코드는 `쪽목록.js` 에 읽는 순서(위→아래, 왼→오른쪽)대로 적는다.

## 순서

```
node 검증/점만들기.js    # 색판 중심 좌표를 찾아 점.json 으로 저장
node 검증/보고.js        # 적중률 (전체·쪽별·카테고리별)
node 검증/진단.js        # 사진색이 DB색에서 어느 방향으로 어긋나는가
node 검증/분해.js        # 오차 중 보정 가능한 몫과 남는 몫
node 검증/천장.js        # 카메라 보정이 완벽했다면 몇 %인가
node 검증/쓸기.js        # 상한·대비가중치를 바꿔가며 적중률 비교
```

`격자시험.js` 는 찾은 색판 위치를 사진 위에 코드와 함께 그린다.
**자동 검출을 믿지 말고 이 그림을 눈으로 확인한 쪽만** `점만들기.js` 의 `확인됨` 에 넣는다.

## 색판 위치를 어떻게 잡는가

흰색 페이지는 색판과 종이의 밝기 차가 15 이하라 자동 검출이 16개 중 6개밖에 못 잡는다.
그래서 두 단계로 한다.

1. `색판찾기.js` — 조명 기울기를 2차 곡면으로 보정하고, 침식으로 붙은 색판을 떼어 낸 뒤 연결 요소를 찾는다
2. `격자.js` — 잡힌 몇 개로 (칸,줄)→(x,y) 아핀 격자를 역산해 **놓친 칸까지 채운다**

`측정.js` 는 앱(`film_app.js`)과 똑같은 순서를 밟는다.
EXIF 회전 → 긴 변 1400 축소 → 반지름 폭×3.5% 의 원 → `영역색()` → `M.검색()`.
이 순서가 어긋나면 측정값이 앱의 실제 동작과 달라진다.

## 2026-09-06 첫 측정 결과 (영림 샘플북 8쪽, 87건)

| 조건 | 5위 안에 정답 |
|---|---|
| 현재 설정 (보정 없음, ΔE 상한 5) | **5.7%** |
| 흰점 보정 + 상한 해제 | 9.2% |
| 카메라 보정이 완벽했다고 가정 | **46.0%** (우드 67~83%) |

- 사진색과 DB색의 ΔE 중앙값 **8.41** — 87건 중 74건이 ΔE 상한 5를 넘어 후보에서 아예 빠졌다
- b\* 가 94% 같은 방향으로 −7.75 치우쳤다 → 자동 화이트밸런스
- L\* 는 쪽마다 −14 ~ +11 로 흔들린다 → 자동 노출
- `kL=2` 는 L\* 만 눌러준다. 정작 가장 일관되게 틀리는 축은 b\* 다
- `대비가중치` 0.15 ↔ 0 은 결과를 거의 바꾸지 않는다 — 병목이 아니다

메탈·채도 높은 색은 샘플북 인쇄가 원본 색을 못 따라가므로(오프셋 인쇄 색역)
그 쪽 숫자는 도구가 아니라 시험지 탓이 섞여 있다.
